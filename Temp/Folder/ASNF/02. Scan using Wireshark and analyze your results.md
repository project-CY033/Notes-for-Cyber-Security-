**Perform Network Scanning Using Nmap and Analyze Results Using Wireshark**

---

## 🎯 **Objective:**

To perform various types of scans (host scan, port scan, OS fingerprinting) using **Nmap** and analyze the packet-level network traffic using **Wireshark**.

---

## 🧰 **Tools Required:**

* Wireshark (Packet analyzer)
* Nmap (Network scanner)
* Windows/Linux machine (with administrator/root privileges)
* A neighbor machine on the same LAN
* Internet access for external scan (e.g., `scanme.nmap.org`)

---

## 🔧 **Before You Start:**

1. **Install Wireshark** from: [https://www.wireshark.org/](https://www.wireshark.org/)
2. **Install Nmap** from: [https://nmap.org/download.html](https://nmap.org/download.html)
3. Make sure you are on the same network as the target (for neighbor machine scan).
4. Run **both tools as Administrator/Root** for full functionality.

---

## 🔬 **Experiment Steps and Analysis**

---

### ✅ **(a) Analyze TCP Session**

#### **Steps:**

1. Open **Wireshark** and start a capture on your active network interface (e.g., Wi-Fi or Ethernet).
2. Initiate a TCP-based connection (open a website like `http://example.com` or use `telnet google.com 80`).
3. In Wireshark, use filter:

   ```
   tcp
   ```
4. Identify a TCP stream:

   * Right-click any TCP packet → Follow → TCP Stream.
   * This shows the entire TCP session (3-way handshake, data exchange, termination).

#### **Analysis:**

* Look for:

  * **SYN, SYN-ACK, ACK** (3-way handshake)
  * **Push ACKs** with data
  * **FIN/ACK** packets at termination
* This verifies session initiation, data transfer, and proper termination.

---

### ✅ **(b) Perform and Analyze These Scans**

---

#### 🔹 **(i) ICMP Host Scan within Same Network**

##### **Steps:**

1. Open **Wireshark** and begin capture on active interface.
2. In **Command Prompt / Terminal**, run:

   ```bash
   nmap -sP [NEIGHBOR_IP]
   ```

   Example: `nmap -sP 192.168.1.5`
3. Stop the capture after scan completes.
4. Apply Wireshark filter:

   ```
   arp or icmp
   ```

##### **Analysis:**

* **ARP Packets**: Shows MAC address resolution (used to discover host presence).
* **ICMP Echo Requests/Replies**: Ping packets showing host is alive.
* Observe:

  * Source and destination IPs
  * Type 8 (Echo Request), Type 0 (Echo Reply)

---

#### 🔹 **(ii) ICMP Scan Outside Local Subnet (e.g., `scanme.nmap.org`)**

##### **Steps:**

1. Start a new Wireshark capture.
2. Run:

   ```bash
   nmap -sP scanme.nmap.org
   ```
3. Stop capture.
4. Filter with:

   ```
   arp or icmp
   ```

##### **Comparison with (i):**

* Likely **no ARP packets** (ARP works only in local subnet).
* Only **ICMP packets** go through the router.
* May see some **"Destination unreachable"** responses depending on firewall policies.

---

#### 🔹 **(iii) TCP SYN Scan + OS Fingerprinting**

##### **Steps:**

1. Start a new Wireshark capture.
2. Run:

   ```bash
   nmap -O [NEIGHBOR_IP]
   ```

   Example: `nmap -O 192.168.1.5`
3. Let the scan complete; then stop capture.
4. Use filter:

   ```
   ip.src == [YOUR_IP]
   ```

##### **Analysis:**

* Look for:

  * TCP packets with SYN flag (nmap sends SYN to ports).
  * RST or SYN-ACK responses from target (shows open/closed ports).
  * OS fingerprinting: Look at TTL values, TCP window size, and sequence number patterns.
* Helps determine:

  * Open ports (based on SYN-ACK responses)
  * Target OS (based on TCP/IP stack behavior)

This experiment demonstrates how network scanning works and how to analyze packet-level data using Wireshark. Different scans generate distinct packet signatures (ARP, ICMP, TCP), which can be observed and analyzed to understand how hosts and networks communicate and respond to probes.
