# 6. To spoof IP address of your own system using Kali Linux

 
---

## 🔐 **Experiment 6: IP Address Spoofing on Kali Linux**

---

### 🎯 **Objective:**

To spoof the IP address of your own system using Kali Linux tools to understand how attackers might forge IP addresses and how such activities can be detected and mitigated.

---

### 🧰 **Tools Required:**

* Kali Linux (pre-installed tools)
* `hping3` or `scapy` (packet crafting tools)
* `ifconfig` or `ip` command (network interface management)
* Optional: Wireshark or tcpdump (for packet analysis)

---

### ⚠️ **Warning:**

This experiment should be done in a **controlled lab environment only** (such as on a VM or isolated network). IP spoofing can be illegal if misused or done on public networks.

---

## ✅ **Steps to Perform the Experiment:**

---

### 🔧 **Method 1: Using `hping3` for IP Spoofing**

`hping3` allows crafting packets with a forged source IP address.

#### Step-by-step:

1. **Open Terminal** on Kali Linux.

2. **Check your actual IP address:**

   ```bash
   ip a
   ```

3. **Use `hping3` to spoof an IP:**

   ```bash
   sudo hping3 -a 192.168.1.100 -S -p 80 192.168.1.1
   ```

   * `-a 192.168.1.100` — This is the **fake (spoofed) IP address** you are pretending to be.
   * `-S` — Send a TCP SYN packet.
   * `-p 80` — Target port 80 (HTTP).
   * `192.168.1.1` — The destination IP (target machine on the same network).

4. **Analyze using Wireshark/tcpdump** on the target or a sniffer system:

   * Observe the spoofed IP in the packet headers.

---

### 🧪 **Method 2: Using Scapy for IP Spoofing**

Scapy is a powerful Python-based packet manipulation tool.

#### Steps:

1. **Run Scapy:**

   ```bash
   sudo scapy
   ```

2. **Send a spoofed packet:**

   ```python
   send(IP(src="192.168.1.100", dst="192.168.1.1")/ICMP())
   ```

   * This sends an ICMP packet (ping) with a spoofed source IP.

3. **Check results using tcpdump or Wireshark** on the target.

---

### 📌 Note:

* IP spoofing **only fakes the source IP** — it doesn’t allow two-way communication. The response will go to the spoofed IP, not to the attacker.
* You can only **send**, not **receive** spoofed traffic unless additional tricks like ARP spoofing or MITM are used.

---

## 📊 **Analysis:**

| Parameter           | Observation                           |
| ------------------- | ------------------------------------- |
| Source IP in packet | Spoofed/fake IP                       |
| Can target reply?   | No (unless routed back by ARP tricks) |
| Packet behavior     | One-way communication                 |

---

## 🔍 **Detection and Mitigation:**

* Use **Ingress Filtering** (RFC 2827): Block packets with source IPs not belonging to your network.
* Monitor using **IDS/IPS systems** like Snort or Suricata.
* Log unusual activity from non-existent internal IPs.
