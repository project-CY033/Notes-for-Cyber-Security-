## **3. Network Analysis using Wireshark**

---

### **Objective:**

To analyze network traffic using **Wireshark** by monitoring:

* TCP and HTTP slowdowns
* Performing **Packet Sniffing**

---

### **A. Traffic Monitoring**

#### **(i) TCP Slow Down Analysis**

**Goal:**
To detect anomalies such as retransmissions, delays, or duplicate ACKs which indicate TCP performance issues.

**Steps to Perform in Wireshark:**

1. **Start Wireshark**
   Launch Wireshark and begin capturing on the active network interface (usually `Wi-Fi` or `Ethernet`).

2. **Generate TCP Traffic**
   Open a web browser or start a download to create TCP traffic.

3. **Filter for TCP Traffic**
   Use the filter:

   ```
   tcp
   ```

4. **Look for Indicators of Slowdown:**

   * Use **"Statistics → TCP Stream Graphs → Round Trip Time Graph"**
   * Look for high latency or spikes.
   * Observe **"\[TCP Retransmission]"**, **"\[TCP Dup ACK]"**, or **"\[TCP Out-of-Order]"** packets.

5. **Interpret Results**
   If there are frequent retransmissions or delays, the connection may be congested or unstable.

---

#### **(ii) HTTP Slow Down Analysis**

**Goal:**
Identify delays in HTTP requests or responses, often due to server-side slowness, congestion, or dropped packets.

**Steps:**

1. **Continue Capture or Start New One**

2. **Generate HTTP Traffic**
   Visit websites using HTTP or tools like `curl http://example.com`.

3. **Apply HTTP Filter:**

   ```
   http
   ```

4. **Check Request/Response Times**
   Right-click an HTTP packet → Follow → HTTP Stream.
   Check how long the server takes to respond.

5. **Use “Statistics → HTTP”**
   This shows request/response delays, throughput, and errors.

6. **Identify Slow Transactions**
   Any HTTP request taking more than 2–3 seconds is suspicious and may indicate a slowdown.

---

### **B. Packet Sniffing**

**Goal:**
To capture and analyze network packets in real-time to observe protocols, IPs, ports, and potential threats.

**Steps:**

1. **Start Wireshark**
   Choose the right interface and click “Start Capture.”

2. **Capture Traffic**
   Let it run while performing normal network activities (browsing, pinging, etc.).

3. **Use Filters to Analyze Traffic:**

   * For all IP traffic:

     ```
     ip
     ```
   * For ICMP:

     ```
     icmp
     ```
   * For ARP:

     ```
     arp
     ```
   * For DNS:

     ```
     dns
     ```

4. **Inspect Individual Packets**
   Click on any packet to view detailed layer-wise information (Ethernet, IP, TCP/UDP, etc.)

5. **Save the Capture**
   File → Save As → for future analysis or documentation.

---

### **Conclusion:**

Wireshark provides powerful visibility into network behavior.

* TCP and HTTP slowdowns help diagnose performance issues.
* Packet sniffing helps in understanding protocol-level communication and identifying threats or abnormal behavior.

---

### **Precaution:**

Ensure you're authorized to sniff traffic on a network. Unauthorized packet capture may violate privacy or network policies.
