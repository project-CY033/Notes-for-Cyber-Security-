# NSVA lab-4 (Netcat usage on TCP/UDP ports)

---

### 🔍 **Objective:**

To understand and use **Netcat (nc)** for TCP and UDP communication to demonstrate its usage as a network diagnostic and penetration testing tool.

---

### 🔧 **Tools Required:**

* **Netcat (nc)** — Pre-installed on most Linux systems.
* Two terminal windows OR two machines (attacker & victim)

  * OR a single machine using different terminal sessions.
* Kali Linux or any Linux distro with Netcat.

---

### 🔌 **Experiment 4: Netcat Usage on TCP/UDP Ports**

#### ✅ **Part A: TCP Communication using Netcat**

##### 📌 Step 1: Setup Listener (Server) on TCP Port

On **Terminal 1 (Listener/Server)**:

```bash
nc -l -p 1234
```

* `-l` : Listen mode
* `-p 1234` : Port number 1234

This will make the machine listen on **TCP port 1234**.

---

##### 📌 Step 2: Connect to Listener from Another Terminal (Client)

On **Terminal 2 (Client)**:

```bash
nc <Server-IP> 1234
```

Example (on same machine):

```bash
nc 127.0.0.1 1234
```

Now type a message on either side and see it appear on the other terminal — showing successful TCP communication.

---

#### ✅ **Part B: UDP Communication using Netcat**

##### 📌 Step 1: Setup Listener on UDP Port

On **Terminal 1**:

```bash
nc -u -l -p 4321
```

* `-u` : Use UDP instead of TCP

---

##### 📌 Step 2: Send Message via UDP

On **Terminal 2**:

```bash
nc -u <Server-IP> 4321
```

Example:

```bash
nc -u 127.0.0.1 4321
```

Now type and send the message.

> 🔹 Note: UDP is **connectionless**, so data is sent without checking if the receiver is listening. Unlike TCP, there is no acknowledgment.

---

### 🔐 **Additional Usage Scenarios**

#### ✔ Port Scanning:

```bash
nc -zv <Target-IP> 20-100
```

* `-z` : Zero I/O mode (for scanning)
* `-v` : Verbose output

Scans ports 20 to 100.

#### ✔ Banner Grabbing (Example: HTTP)

```bash
nc <target-ip> 80
```

Then type:

```http
HEAD / HTTP/1.0
```

Press Enter twice. You'll see the HTTP server’s response headers.

---

### 🧪 **Observation:**

* TCP communication is reliable and connection-oriented.
* UDP communication is faster but connectionless and not reliable.
* Netcat is very useful for debugging network services, port scanning, reverse shells, and transferring files.

---

### 📓 **Conclusion:**

This experiment demonstrates the use of **Netcat** for communication over **TCP and UDP** ports, which is vital in **vulnerability assessment**, **network diagnostics**, and **penetration testing**. Understanding how services respond on different ports helps assess potential vulnerabilities in a network system.
